## What was built
- **New** `scripts/normalize_graph_vocab.py` — pure `normalize_relationships()` + CLI (`--dry-run` / `--apply`, self-backing-up). Auto-remaps the malformed `owns_by` → `owned_by` (string-only relabel, no direction change); reports all other off-enum types for human review; idempotent; never drops edges.
- **New** `tests/test_normalize_graph_vocab.py` — 6 tests (remap correctness, count preservation, idempotency, no-input-mutation, off-enum-reported-not-removed, JSON round-trip).
- `scripts/ingest.py` — pinned the relationship enum in the extraction prompt (explicit "MUST be exactly one of … never invent a new type" rule) so future ingests stop producing off-enum types.

## Design decision (mid-item judgment)
Auto-fix **only** `owns_by`→`owned_by` (an unambiguous malformed spelling of the same relation). The other off-enum types (`owns` 88, `enables` 5, `used_by` 5, `generates`/`blocks`/`triggers`/`manages`/`supports` 2 each, `provides`/`applies_to`/`associates`/`receives` 1 each) are **semantically-distinct verbs, not misspellings** — folding them would change meaning/direction, so they're reported for review, not auto-merged. The enum-pin stops the drift going forward. (SOUL: precision over speed; don't destroy meaning.)
